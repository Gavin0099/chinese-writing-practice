# UX 任務 2：改版方案與驗收計畫（Phase 1）

日期：2026-11-12。基準：`901cb8d`。依據：[問題清單](ISSUES.md) 的 U1–U8。這是**待實作方案**；本階段只新增兩份文件，沒有更動網站或既有檔案。瀏覽器觀察受阻，改版前示意來自原始碼，改版後示意是設計意圖；兩者都不是截圖。

## 目標與取捨

先讓家長辨認「老師詞庫」「新增／批次輸入」「用詞庫出卷」三個目的，再在同一工作區完成它們。資料保存說明需要回答「目前操作哪一份資料」以及「另一台裝置如何取得」，不增加新的同步功能。

沿用現有字型、色彩、原生表單與頁面技術。調整層級、順序、留白與可點範圍均須對應問題；不另訂品牌視覺，不引入套件、圖片、字型或設計指南。也不新增儀表板、搜尋、排序、分頁、OCR、資料模型或帳號流程。

詞庫仍是一頁完成管理與出卷；`exam.html` 繼續只負責已存考卷預覽。以頁內捷徑與原生 disclosure 縮短路徑，避免新增分頁路由或複製表單。實際 DOM 順序要與視覺／鍵盤順序一致，不單靠 CSS `order` 把畫面和 Tab 順序拆開。

## 重要的 DOM 與狀態接線

1. **詞庫頁頂部保持一個目前班級選擇器。** `#bookSelect` 的資料、選擇規則和 change handler 不動。沒有班級時，`#bookDetails` 的原建立表單仍是必要步驟；年級、學期、學年度的預設與 required 驗證不變，不為縮短介面隱藏無預設的必填欄位。
2. **頁內入口只改呈現與焦點。** 新增／批次捷徑展開對應 disclosure，然後聚焦其現有欄位；`editWord()` 只增加展開單筆容器的步驟。使用者仍可回到出卷區，已輸入文字保留，既有 dirty／離頁 guard 不被繞過。
3. **出卷 section 保持唯一。** 保留原提交、歷史渲染與連結，不把相同 id／name 複製到卡片或工具列。首頁的出卷深連結只選擇頁內位置；沒有班級不能假造可用題庫，改導向原建立區。已存在的 `?book=` 與 `?cloud=1` 必須完整保留。
4. **保存地點與保存結果分開。** 本機標籤只描述當前資料來源；「已儲存／已同步」仍由原成功路徑給出。雲端讀取失敗時保留 `main.inert` 與既有錯誤入口，不顯示假的本機成功 fallback。
5. **不要改成自動同步的承諾。** 跨裝置說明應為「另一台裝置使用同一帳號，開啟雲端詞庫；本機詞庫仍屬這個瀏覽器」。首次上傳是否可用、雲端已有資料時的保護與備份方式，全部沿用既有流程。

## 風險與處理

| 風險 | 影響 | 最小處理與退出條件 |
| --- | --- | --- |
| 本次無可用瀏覽器觀察 | 改版前的首屏位置、尺寸與滾動假設可能錯誤 | 下一階段先補 baseline 截圖與實走，再調整層級；若證據不支持某項版面改動就縮小方案，不擴大重構 |

| 首頁 Bootstrap 與既有 CSS 疊加 | 新尺寸／導覽規則被 cascade 覆蓋，或誤碰 worksheet | 只用限定 selector 與 screen media，保持 stylesheet 順序及列印 DOM；以 computed layout 實測 |
| 收合表單後原 focus() 找不到可見輸入 | 編輯／成功後鍵盤流程退步 | 在既有編輯入口增加單純展開與焦點接線；不重寫保存／確認邏輯；測 Tab 與 edit/save/cancel |

| 狀態提示被誤當成新的同步狀態機 | 提早顯示成功或吞掉衝突 | UI 只消費原結果；不加 localStorage key、輪詢、樂觀成功或重試邏輯 |
