### U1 — 老師詞庫入口服從練習紙引導

- **位置：** `index.html:20` 的 `#onboardingModal`、`index.html:59` 的 `.main-tools`、`index.html:66` 的 `.hero-section`；`script.js:71`；`storageManager.js` 的 `isNewUser()`。
- **原始碼證據：** 首次卡片順序為年級 → 學期 → 開始練習 → 國字查詢 → 老師詞庫。回訪主內容是練習紙推薦；詞庫仍是導覽文字連結。首次判斷只看 `write_practice_data`，不看詞庫是否已有資料，因此只用過詞庫的家長再到首頁，仍可能再次看到練習紙 onboarding。
- **390px 家長可能遇到：** 把先選孩子年級誤認為進詞庫的必要步驟。卡片 CSS 有 `3.5rem` 內距、年級固定 3 欄，但沒有窄版專用調整；文字換行／卡片超高是待查風險。實際首屏、遮擋與詞庫連結 y 座標：**NOT OBSERVED**。
- **1280px 家長可能遇到：** 雖然同樣存在 1 次點擊的詞庫直達連結，主要 CTA 仍指向練習紙，尚未清楚呈現老師指定詞語這個獨立目的。可見性及注意力分布：**NOT OBSERVED**。
- **影響與處置：** high；T1、T3、A1。優先提升現有直達入口並說明不必先設定練習紙；不能寫成「目前沒有詞庫入口」或改變首次使用儲存判斷。

### U2 — 導覽層級與位置感不一致

- **位置：** 六頁的 header；`vocabulary.css:1`、`learning.css:15`、`styles.css:1187`。
- **原始碼證據：** 首頁有 2 個工具連結，詞庫／學習頁各 4 個，同步頁有 3 個「本機」工具，備份頁有 2 個，考卷頁只有返回詞庫。詞庫與學習頁沒有導覽中的目前頁標記。詞庫的 header 使用 flex wrap；同步入口在首頁沒有直接連結。
- **390px 家長可能遇到：** 四個等級相同的連結需要閱讀與可能換列，與「現在要輸入還是出卷」競爭空間。實際列數、header 高度、是否超出首屏：**NOT OBSERVED**，不把「占掉半頁」當成事實。
- **1280px 家長可能遇到：** 跨頁後可用連結與名稱改變，進入備份頁後沒有直接同步連結；版面較寬也不會自動補上導覽一致性。實際導航時間：**NOT OBSERVED**。
- **影響與處置：** medium；T1、T4、A6。整理主要入口與次要工具，保留考卷返回目前班級的上下文。不得因統一導覽而丟失 `cloud=1` 或班級／考卷參數。

### U3 — 批次入口排在單筆輸入之後

- **位置：** `vocabulary.html:49` 的新增詞語 section、`#wordForm`、`#batchDetails`、`#batchForm`；`vocabulary.css:8`、`:45`。
- **原始碼證據：** 批次 summary 位於課次、詞語、注音、說明、挖空選擇、核對 checkbox、儲存按鈕和單筆 notice 之後。批次區預設收合。窄版在 `max-width:44rem` 變成單欄；寬版仍把批次放在左側單筆表單下方。
- **390px 家長可能遇到：** 手上有老師整張清單，卻先被邀請逐筆輸入；必須先找到較後面的批次入口。實際需要幾次滑動、批次 summary 是否在首屏外：**NOT OBSERVED**。
- **1280px 家長可能遇到：** 右側可看到清單，但批次不是與單筆平行的選項，仍須沿左欄往後找。實際 y 座標：**NOT OBSERVED**。
- **影響與處置：** high；T2、A1。把單筆／批次選擇提前；保留現有預覽、逐行錯誤、人工核對、儲存四段含義，不能把「貼上」改成未經核對即出題。

### U4 — 出卷和已存考卷被清單長度推後

- **位置：** `vocabulary.html:44` 的 `#goToExam`、`:89` 的 `.exam-panel`、`#examForm`、`#examList`；`vocabulary.mjs:304`、`:331`；`exam.mjs` 的試卷讀取分支。
- **原始碼證據：** 出卷 section 位於整個 `.vocabulary-columns` 之後；手機單欄時先是單筆／批次，再是全部可見詞語，再到出卷。桌面則在新增與清單兩欄之後。每個詞語都建立一列，沒有分頁；`content-visibility:auto` 是渲染最佳化，不是把清單從閱讀順序移除。已有 `#goToExam` 錨點捷徑，CSS 最小高度 `2.75rem`，有班級就顯示。`exam.html` 本身是既有試卷預覽，沒有 id 時顯示找不到考卷，不是新建入口。
- **390px 家長可能遇到：** 回訪只想出卷，若沒注意到班級卡內的文字捷徑，會先經過新增與整份清單。已有捷徑意味著不必真的填新增表單；問題是優先順序與發現性。實際長清單捲動距離：**NOT OBSERVED**。
- **1280px 家長可能遇到：** 出卷不與詞庫選擇並列，清單較長時也會把下一個 section 推後。產生與開啟預覽是兩次不同操作；本次沒有觀察是否造成困惑。
- **影響與處置：** high；T3、A3。把出卷移到管理表單／長清單之前，強化現有捷徑與考卷紀錄；不更改抽題、種子或考卷 renderer。

### U5 — 44×44px 的可操作範圍缺乏一致保證

- **位置：** `vocabulary.css:42` 的控制項規則、`:19` 的 `.subpanel`、`learning.css:16` 的 header link、`:27` 的 summary；首頁 `.btn-text`（`styles.css:1350`）。
- **原始碼證據：** 詞庫／同步的 `select,input,button` 設定 `min-height:2.65rem`；以 16px 根字級換算為 **42.4px，而非實測高度**。header 連結與 summary 沒有 44px 最小高度；外層 `.subpanel` 的 padding 不是 summary 本身的點擊框。首頁 `.btn-text` 有 padding，但沒有最小寬高保證。正面例外：`#goToExam`、清單按鈕、考卷歷史連結、核對及挖空 label 已指定 `2.75rem` 高度，不應全部描述成過小。
- **390px 家長可能遇到：** 點導覽、展開批次或操作課次時，手指可點範圍可能不足。每個元素的 bounding rectangle、有效 label 點擊面積：**NOT OBSERVED**；目前是可由 CSS 證明的保證不足，尚不是實測全頁失敗清單。
- **1280px 家長可能遇到：** 同樣的宣告仍適用；滑鼠較容易點不代表手機驗收達標。鍵盤焦點與點擊框：**NOT OBSERVED**。
- **影響與處置：** high；T1–T4、A2。只針對螢幕介面的互動元素補足最小寬高；checkbox 可保留原生小方框，但所屬可點 label 需要達標。不得擴大考卷格或練習紙格。

### U6 — 「資料存哪裡」的說明互相衝突
