## 任務與驗收對照

- T1：進入老師詞庫。
- T2：新增或批次輸入老師指定的詞語。
- T3：使用既有詞庫產生考卷，並能重開既有考卷。
- T4：理解手機與電腦之間的本機／雲端資料保存。
- A1：首次與回訪都能完成；A2：手機主要目標至少 44×44 CSS px；A3：不穿過整頁新增詞語表單即可找到出卷；A4：資料狀態清楚；A5：測試與列印基準不變；A6：Windows Chrome 兩尺寸視覺／鍵盤及實機缺口記錄。

嚴重度是任務風險判斷：**high** 為會顯著妨礙核心任務或造成保存狀態誤解；**medium** 為有既有替代路徑但增加理解／操作成本；**low** 為次要易讀性改善。全部為基準既存問題，不是此次新增的 regression。

## 值得保留的現況

- 首頁與首次設定畫面**都已經有**直達老師詞庫的連結；不必先填年級才能進詞庫。
- 有班級時，`#goToExam` 會顯示，直接跳到 `#examHeading`。不應將問題寫成「完全沒有出卷入口」或「必須捲過全部詞語」。
- 批次有預覽、逐列錯誤、部分成功與錯誤列保留；編輯／切班有未存內容保護。這些流程值得保持。
- 出卷區已有實際題池數、保存的考卷和明確預覽／列印操作；備份還原已有預覽與取代確認。沒有證據需要重寫這些邏輯。

## 問題清單

### U1 — 首頁的首要任務仍是練習紙，老師詞庫入口層級較弱

- **位置**：`index.html:20–61` 的 `#onboardingModal`、`.main-tools`；`:69–95` 的推薦練習紙與自訂入口；`script.js:75–128`。
- **證據**：首次設定主文為「選擇年級與學期，系統會推薦練習紙」，6 個年級按鈕、2 個學期按鈕後才放兩個工具連結。回訪主卡以練習紙為內容，老師詞庫在 header。首頁沒有直接的保存／同步入口。這些是來源中的內容及數量，不是畫面計時。
- **390px 家長風險**：帶著老師詞語進站時，可能先處理與目標無關的年級選擇；header 允許折行，但實際行數、入口是否首屏、首次提示是否遮住入口 **NOT OBSERVED**。來源已有直達連結，不能說流程被強制擋住。
- **1280px 家長風險**：即使有較寬空間，語意上的主操作仍是練習紙，無法由首頁主內容辨認「貼老師詞語 → 出卷」。實際視覺權重 **NOT OBSERVED**。
- **阻礙**：T1、T2；A1、A3。**嚴重度：high**，關於入口辨識，不是功能不存在。

### U2 — 回訪出卷區排在輸入與詞語清單之後，捷徑沒有成為主要動作

- **位置**：`vocabulary.html:26–104` 的 `#goToExam`、`.vocabulary-columns`、`.exam-panel`；`vocabulary.mjs:157–173,302–324`。
- **證據**：DOM 順序是班級 → 新增單筆／批次 → 班級詞語清單 → 出卷 → 已儲存考卷。`vocabulary.css:45–49` 在 44rem 以下改成單欄。清單無分頁，出卷區在清單之後；但上方既有錨點可直接到出卷。
- **390px 家長風險**：未辨認捷徑的回訪家長會先遇到完整輸入流程；詞語愈多，順讀路徑愈長。實際 Y 座標、所需滑動次數及捷徑可見性 **NOT OBSERVED**。
- **1280px 家長風險**：新增表單與清單是兩欄，但出卷仍在整組 grid 下方；較長一欄會推後出卷。實際高度 **NOT OBSERVED**。
- **阻礙**：T3；A1、A3。**嚴重度：high**，已有捷徑可緩解；不是所有使用者都必須穿過表單。

### U3 — 批次輸入被當成單筆表單的附屬功能

- **位置**：`vocabulary.html:49–76` 的 `#wordForm`、`#batchDetails`、`#batchForm`。
- **證據**：批次 `<details>` 沒有 `open`，且在課次、詞語、逐字注音、挖空字、核對框、儲存及通知之後。批次另有課次欄、貼上欄、預覽、可選核對、最後儲存；不是貼上即存入。
- **390px 家長風險**：拿到整份老師清單時，先遇到單筆表單，容易逐字重複操作；找到批次後仍需理解預覽與儲存的分工。實際捲動及完成步數 **NOT OBSERVED**。
- **1280px 家長風險**：寬畫面不改變批次位於左欄表單尾端的 DOM 順序與預設收合；是否被看見 **NOT OBSERVED**。
- **阻礙**：T2；A1、A3。**嚴重度：high**，對大量老師指定詞語特別明顯。

### U4 — 主要操作沒有一致的 44×44px 保證，說明字級也較小

- **位置**：`vocabulary.css:1,6,15–20,27,37,42`；`learning.css:14–16,27,32–42`；`styles.css:1350–1358`。
- **證據**：一般 `select,input,button` 最低高度為 `2.65rem`；導覽 `<a>`、`summary` 沒有 44px 最低尺寸。相較之下，`#goToExam`、詞列按鈕、核對標籤及考卷連結已用 `2.75rem`。提示 `.92rem`、詞列 metadata `.9rem`。若根字級為 16px，這些名目值分別為 42.4、44、14.72、14.4px；**這是 CSS 換算，不是 computed style 或 hitbox 實測**。內容也可能將目標撐大。
- **390px 家長風險**：收合批次、換班、儲存和導覽是高頻觸控操作，尺寸規則未保證驗收；細小提示承擔注音／資料來源等重要資訊。實際尺寸、對比與誤觸 **NOT OBSERVED**。
- **1280px 家長風險**：滑鼠環境可能較不敏感，但鍵盤焦點和觸控螢幕仍需一致目標；實際焦點顯示 **NOT OBSERVED**。來源已有 `:focus-visible`，不能報成完全無焦點樣式。
- **阻礙**：T1–T4；A2、A6。**嚴重度：medium**，驗收風險明確，實際不合格數量未知。

### U5 — 本機／雲端的說明及成功通知互相不一致

- **位置**：`vocabulary.html:24`；`vocabulary.mjs:198,235,282,341`；`learning.html:60`；`sync.html:17–19,54–64`；`sync.mjs:39–50,190–204,264–269`；`backup.html:19–21`。唯讀佐證：`cloudStorage.mjs:151–160,206–211`。
- **證據**：雲端模式插入「看到已同步後，即可在其他裝置開啟」，但詞庫 intro 仍說「詞庫和考卷存在這個瀏覽器」，學習頁仍說習寫紀錄只在此瀏覽器。單筆／出卷成功有依模式顯示「已同步」，批次成功則固定「已儲存」。登入前的成功讀取 session 分支把 `#loginNotice` 清空。備份頁標題未指明本機，但其模組使用本機資料。
- **390px 家長風險**：手機存入一批詞語後，可能不知道是否已到電腦可用的家庭資料；來源狀態與成功訊息可能不在同一視野，實際距離 **NOT OBSERVED**。
- **1280px 家長風險**：較寬畫面不會消除互相矛盾的文字；使用者仍可能把登入、首次匯入和持續同步當成同一件事。真實登入與雙裝置行為 **NOT OBSERVED**。
- **重要邊界**：本機頁不是登入後自動變雲端頁；`?cloud=1` 才開雲端。同步頁上方刻意連本機工具，家庭區才連雲端。已有雲端資料時不提供覆寫式首次匯入。這些是正確的既有分流，不能為統一導覽而消除。
- **阻礙**：T4，並影響 T2、T3 的成果理解；A1、A4。**嚴重度：high**。

### U6 — 空詞庫缺少下一步引導，「已存／已核對／可抽題」容易混讀

- **位置**：`vocabulary.html:26–44,55,79–98`；`vocabulary.mjs:109–129,157–173,184–199,286–299`。唯讀佐證：`examData.mjs:12–25`。
- **證據**：無班級時自動展開建立表單，有 5 個必填與 1 個選填欄位；年級／學期有預設，學年度會帶入，因此不能說需要手填五欄，真正空白的必填文字欄位是名稱、出版社兩欄。新班級零詞語只顯示「這裡還沒有詞語」。清單的「N 個可出題」實際按 `confirmed` 計數；題池另會合併相同提示及排除多答案提示，兩個數字不保證相同。
- **390px 家長風險**：第一次建立班級時，不清楚這只是保存老師指定內容的容器；貼詞後見「已儲存」也不等於可抽滿 15 題。實際操作／錯誤回復 **NOT OBSERVED**。
- **1280px 家長風險**：空白清單和完整輸入區同時存在，未指向「單筆／批次」選擇；看到兩個不同的可用數字時仍需自行理解。實際畫面 **NOT OBSERVED**。
- **阻礙**：T2、T3；A1、A4。**嚴重度：medium**。既有逐字注音說明及題池排除提示需保留。

### U7 — 出卷的進階用語與「建立後再開啟」順序不夠直白

- **位置**：`vocabulary.html:89–103` 的 `[name=seed]`、`#examPool`、`#examList`；`vocabulary.mjs:329–342`；`exam.html:15–25`。
- **證據**：出卷有 3 個必填數字欄（預設 1／8／15）及 1 個可選「亂數種子」。手機 CSS 仍把三個數字欄排同一列，種子另列。提交會保存考卷、顯示訊息、聚焦最新的「開啟考卷與解答」，**不會自動跳到預覽**。
- **390px 家長風險**：家長需先理解技術用語，按「產生考卷與解答」後又需找到開啟連結；實際焦點是否落入可視區、欄位是否擁擠 **NOT OBSERVED**。
- **1280px 家長風險**：四欄並排讓可選重現設定與每日必填選項同等突出；產生與開啟仍是兩個動作。實際權重 **NOT OBSERVED**。
- **阻礙**：T3；A1、A3、A6。**嚴重度：medium**。這是呈現及預期問題，不建議改成自動導航或更換種子算法。

### U8 — 部分輸入限制只在提交後由驗證器說明

- **位置**：`vocabulary.html:52–57,67–69`。唯讀佐證：`vocabularyData.mjs:44–61`。
- **證據**：詞語實際要求 1–10 個國字，至少一個挖空位置，有填注音時需逐字對齊；詞語欄只有例子與 `maxlength=20`。既有說明已交代每字一組、空格分隔與可先存後核對，不應重複加長。
- **390px 家長風險**：手機輸入修正成本較高，選錯格式後才知道限制。實際錯誤頻率、手機鍵盤及內容是否保留 **NOT OBSERVED**。
- **1280px 家長風險**：從試算表貼入時，仍需區分單欄詞語與 Tab 分隔三欄；實際貼上／預覽結果 **NOT OBSERVED**。
- **阻礙**：T2；A1、A6。**嚴重度：medium**。`maxlength` 是 UTF-16 長度，不能直接改成 10 來冒充國字數驗證。

## 來源流程走查紀錄

以下順序是閱讀事件處理得到的路徑，**不是已執行的操作測試，也不是實測步數**。

| 狀態／情境 | 來源確認的順序 | 尚未觀察 |
| --- | --- | --- |
| 首次到首頁 | 首次設定畫面中直接選「老師詞庫與出卷」；無需先選年級 | overlay 實際位置、鍵盤循環、三秒後筆順提示與其互動 |
| 沒有任何班級 | 進詞庫 → 建立班級表單自動展開 → 填名稱／出版社、核對預設資料 → 建立 → 工作區顯示 | 實際完成、重開保存、錯誤焦點 |
| 有班級但零詞語 | 可選單筆儲存或展開批次；出卷區已有 0 題池提示，預設抽題數仍是 15 | 空態畫面、錯誤後恢復 |
| 單筆輸入 | 詞語輸入後預選第一字挖空 → 可填注音並核對 → 儲存 → 詞語欄重新取得焦點 | 滑動、軟鍵盤、未核對時家長理解 |
| 批次輸入 | 展開 → 課次／貼上 → 預覽 → 逐列核對 → 儲存有效列；錯誤列保留 | 成功混合失敗列、重複／空白／無注音資料的真實 UI |
| 回訪已有詞庫 | URL `book` 若有效則選該班，否則選資料中的最後一班；不等同「永遠記得上次班級」 | 重開、切班及未儲存保護 |
| 已有足夠詞語 | 既有出卷錨點 → 範圍／題數 → 產生 → 已儲存紀錄 → 開啟預覽 | 實測點擊數、固定種子重現、最新紀錄可見性 |
| 已有考卷 | 考卷紀錄 → 開啟 → 選考卷／解答／兩者 → 列印 | Windows 預覽、PDF、實體紙本 |
| 手機轉電腦 | 本機可下載備份後在另一裝置還原；或明確進雲端模式，以同帳號開啟。首次本機匯入僅限空白家庭 | Auth、RLS、實機跨裝置、網路失敗與衝突 |

## 下階段觀察缺口

沒有截圖、沒有已量測的首屏位置、沒有操作成功率。應先在可操作環境重現上述情境，再決定首頁／導覽的精確間距與折行方式。不能根據 CSS 欄數斷言 390px 已裁切，也不能因 HTTP 200 宣稱所有流程可用。

Windows Chrome 390×844、1280×800 的 before 截圖與鍵盤走查仍待補；iPhone Safari、真正觸控／軟鍵盤及實體 A4 列印均保留為 **NOT OBSERVED**。本階段未建立 Draft PR；後續提交／PR 交由實驗 harness 的程序處理，不從這份評估取得發布或部署授權。
